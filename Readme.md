# AI QA & Bug Investigation Agent

An AI-powered agent that helps QA engineers investigate software bugs by reasoning over internal documents — requirements, API docs, test cases, bug reports, and QA guidelines.

---

## Goal

> "Login fails after password reset for some users."

Feed a bug description → get a grounded, structured analysis with sources, likely root causes, and recommended tests. No hallucinations — every claim is traced to a real document.

---

## Tech Stack

| Layer | Technology | Notes |
|---|---|---|
| **Embeddings** | `sentence-transformers` (`all-MiniLM-L6-v2`) | Local, CPU, free, no API key |
| **Vector Search** | `faiss-cpu` | Saved to disk — no re-embedding on restart |
| **Agent Framework** | `crewai` | Controlled multi-step workflow with defined tools |
| **LLM** | Configured via `.env` (`OPENAI_API_KEY` or compatible) | Low temperature for factual QA analysis |
| **Data** | Markdown files in `/data` | Fictional CallFlow CRM dataset |
| **Environment** | Python 3.11 + `.venv` | |

## Quick Start

### 1. Clone & set up environment

```bash
git clone <your-repo>
cd ai-qa-bug-agent

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Mac/Linux

pip install -r requirements.txt
```

### 2. Configure your API key

```bash
copy .env.example .env          # Windows
# cp .env.example .env          # Mac/Linux
```

Then open `.env` and set:

```
LLM_API_KEY=your_key_here
```

### 3. Build the FAISS index (run once)

```bash
python ingest.py
```

This reads all files in `/data`, splits them into chunks, embeds them with a local model, and saves:
- `faiss_index/index.faiss` — the vector index
- `faiss_index/metadata.json` — chunk text + metadata

**No internet needed after this step at query time.**

Re-run `ingest.py` only when you add or change files in `/data`.

### 4. Run the agent

```bash
python app/main.py
```

### 5. Run tests

```bash
pytest tests/
```

> The FAISS search tests are automatically skipped if the index has not been built yet. Run `python ingest.py` first to enable them.

## Agent Design (CrewAI)

The agent follows a **controlled sequential workflow** — it cannot freely loop or make unlimited tool calls.

```
START
 ↓
UNDERSTAND (parse bug description)
 ↓
RETRIEVE (hybrid search: FAISS + BM25 + metadata filters → top 10)
 ↓
RERANK (cross-encoder → top 5)
 ↓
ASSESS EVIDENCE
 ↓
Need more info? → YES → Ask user
              → NO
                ↓
             ANALYZE (LLM over top-5 evidence, low temperature)
                ↓
             VALIDATE (grounding checks)
                ↓
             RESPOND (structured output with sources)
```

### CrewAI Tools (3 only)

| Tool | Purpose |
|---|---|
| `search_knowledge_base` | Search requirements, API docs, test cases, QA guidelines |
| `search_bugs` | Search previous bug reports |
| `get_document` | Retrieve the full content of a specific document by ID |

### Hard Limits

| Constraint | Value |
|---|---|
| Max tool calls per investigation | 5 |
| Max retrieved chunks (after reranking) | 5 |
| Max repeated identical tool call | 1 |
| Temperature | Low (0.1–0.2) |

## Anti-Hallucination Rules

- Only make claims supported by retrieved evidence
- Never invent bug IDs, requirement IDs, or test case IDs
- Clearly label: `Confirmed` / `Likely` / `Possible` / `Unknown`
- Say "Insufficient evidence" when appropriate
- Cite the source document ID for every claim
- Never fabricate confidence scores
