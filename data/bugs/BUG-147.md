# BUG-147: Multi-Device Session Collision After Password Change Returning 401

## Summary
Users with simultaneous active sessions on mobile and desktop experience immediate login failure and token rejection after updating their password from one device.

## Reported Environment
Production & Staging

## Steps to Reproduce
1. Log into CallFlow CRM on Laptop (Chrome).
2. Log into CallFlow CRM on Mobile device (iOS Safari).
3. From Laptop, update password in Account Settings.
4. Attempt to log in again on Laptop or Mobile.
5. In 15% of cases, the client enters an authentication loop resulting in repeated 401 Unauthorized errors.

## Root Cause
The JWT refresh mechanism on the secondary device attempted automatic background token refresh using the old `refresh_token` simultaneously as the primary device initiated a login with new credentials. The server-side auth handler encountered a race condition where the old refresh token incremented an invalidation counter, briefly locking the user account out of Redis for 120 seconds.

## Resolution
- Implemented grace period locking: background refresh failures return distinct code `TOKEN_REVOKED_PASSWORD_RESET` rather than triggering rate-limiting locks.
- Frontend clears stored local session keys immediately upon 401 with `TOKEN_REVOKED`.
