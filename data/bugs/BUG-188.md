# BUG-188: User Role Modification Fails to Refresh User JWT Permissions Immediately

## Summary
When an administrator promotes an agent to "Team Lead" or revokes permissions, the user continues seeing their old role privileges until their 15-minute access token naturally expires.

## Reported Environment
Staging & Production

## Root Cause
Access tokens (JWTs) were strictly stateless and did not query the Redis token version or permission cache until token expiry forced a refresh.

## Resolution
Introduced an in-memory revocation bloom filter at the API gateway that checks for recent permission modifications and forces an early token exchange.
