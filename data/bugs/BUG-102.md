# BUG-102: Users Unable to Login After Password Reset Due to Stale Token Cache in Redis

## Summary
After completing the password reset flow, some users receive an "Invalid session or credentials" error when attempting to log in with their new password.

## Reported Environment
Production (US-East Cluster)

## Steps to Reproduce
1. User requests password reset link.
2. User clicks link and submits new password.
3. System confirms password updated.
4. User attempts to log into CallFlow CRM web app using the new password.
5. Login fails with `HTTP 401 Unauthorized`.

## Root Cause
When `POST /api/v1/auth/password-reset/confirm` was processed, the database updated `users.password_hash` and incremented `users.token_version`. However, the Redis cluster cache command `DEL session:{user_id}:*` timed out silently due to a Redis cluster shard failover. As a result:
1. The auth gateway continued reading the old `token_version` cached in Redis.
2. The incoming login request validated the password but compared the minted token against the stale Redis session record, flagging an invalid token version mismatch.

## Solution & Workaround
- Wrapped Redis cache invalidation in a verified retry block with fallback to direct database `token_version` lookup on cache miss.
- Added explicit Redis key eviction on successful login.
